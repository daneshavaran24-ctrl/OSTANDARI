# AGENTS.md

راهنمای کار روی این پروژه برای عامل‌های کدنویس.

این مخزن یک **مونوریپو با سه بخش** است، نه یک پروژه‌ی تک‌جزئی. این فایل در
`agent/` قرار دارد و درباره‌ی بخش ایجنت است، ولی قبل از تغییر هر چیزی
`../README.md` را بخوانید تا معماری کل سیستم را بفهمید.

| پوشه | چیست | ابزار |
|---|---|---|
| `agent/` | ایجنت صوتی روی LiveKit Agents + آواتار Beyond Presence | `uv`، `ruff`، `pytest` |
| `../frontend/` | رابط کاربری گفت‌وگو با Next.js 15 | `pnpm`، ESLint، Prettier |
| `../demo-app/` | اپ دموی «سامانه‌ی دارای مشکل» با Vite | `npm`، ESLint |

## پشته‌ی فعلی

پروژه روی API نسخه‌ی ۱.۸ لایوکیت است — همان چیزی که قالب رسمی
`agent-starter-python` نشان می‌دهد، پس نمونه‌کدهای مستندات با این کد می‌خوانند.

| جزء | انتخاب | چرا |
|---|---|---|
| `livekit-agents` | `[bey,openai]~=1.8.1` | `~=` محدوده را روی ۱.۸.x نگه می‌دارد، پس ارتقای مینور خودکار اتفاق نمی‌افتد |
| پایتون | `>=3.11,<3.15` | کران بالا از خودِ livekit-agents می‌آید؛ CI روی ۳.۱۱، ۳.۱۲ و ۳.۱۳ اجرا می‌شود |
| مدل | `openai.realtime.RealtimeModel` با `gpt-realtime` | صدا → استدلال → صدا، بدون زنجیره‌ی STT/TTS |
| صدا | `cedar` | لحن مردانه‌ی بم که پرامپت فارسی توصیفش می‌کند |
| نویزگیری | `ai_coustics.audio_enhancement(QUAIL_VF_S)` | از اعتبارنامه‌ی LiveKit Cloud استفاده می‌کند و کلید جدا نمی‌خواهد |
| آواتار | `bey.AvatarSession` | Beyond Presence |

مدل و صدا از طریق `OPENAI_REALTIME_MODEL` و `OPENAI_VOICE` قابل تغییرند.

### ترتیب راه‌اندازی در `src/agent.py` تصادفی نیست

```
session.start()  →  avatar.start()  →  ctx.connect()  →  background_audio.start()
```

- `avatar.start()` باید **بعد از** `session.start()` بیاید، چون خروجی صدای نشست را
  با `replace_audio_tail` جایگزین می‌کند؛ اگر زودتر اجرا شود نشستی برای جایگزینی
  وجود ندارد.
- `background_audio.start()` باید **بعد از** `ctx.connect()` بیاید، چون یک ترک
  صوتی روی اتاق منتشر می‌کند و اتاق باید وصل باشد.

### راستی‌آزمایی API

مستندات آنلاین همین نسخه را توصیف می‌کنند، ولی برای امضای دقیق توابع، سورس
نصب‌شده در `.venv` مرجع قطعی است:

```bash
uv run python -c "import inspect; from livekit.plugins import bey; print(inspect.signature(bey.AvatarSession.start))"
```

### ⚠️ `participant.kind` یک عدد است، نه رشته

`src/tools.py` برای پیدا کردن کاربر انسانی، participantهای نوع ایجنت را کنار
می‌گذارد (آواتار Beyond Presence با `.with_kind("agent")` وارد می‌شود). مقایسه
**باید** با enum عددی protobuf باشد:

```python
if participant.kind == rtc.ParticipantKind.PARTICIPANT_KIND_AGENT:
```

مقدار واقعی عدد ۴ است. اگر این را به مقایسه‌ی رشته‌ای برگردانید
(`str(kind).endswith("AGENT")`) بی‌صدا از کار می‌افتد، آواتار کنار گذاشته نمی‌شود و
اعلان‌ها به مقصد اشتباه می‌روند. تست `test_avatar_kind_is_not_detectable_as_a_string`
نگهبان همین مورد است.

## ساختار پروژه

این پروژه‌ی پایتون از `uv` استفاده می‌کند. همیشه برای نصب وابستگی، اجرای ایجنت و
اجرای تست از `uv` استفاده کنید.

کد سطح برنامه در `src/` است. **`src/agent.py` باید نقطه‌ی ورود بماند** — هم
`Dockerfile` و هم `taskfile.yaml` به همین مسیر ارجاع می‌دهند.

```
agent/
├── src/
│   ├── agent.py      ← نقطه‌ی ورود؛ اسمش را عوض نکنید
│   ├── prompts.py    ← دستورهای ایجنت (فارسی)
│   └── tools.py      ← ابزارهای unblock_user و send_email
├── tests/test_agent.py
├── scenarios.yaml
├── Dockerfile
└── taskfile.yaml
```

قالب‌بندی کد را حفظ کنید:

```bash
uv run ruff format
uv run ruff check
```

یا هر سه بررسی با هم، همان چیزی که CI اجرا می‌کند:

```bash
task check     # یا: uv run ruff check && uv run ruff format --check && uv run pytest -q
```

## ⚠️ ایجنت فارسی صحبت می‌کند

`src/prompts.py` به فارسی نوشته شده و `src/agent.py` با سلام فارسی شروع می‌کند.
سناریوهای `scenarios.yaml` هم فارسی‌اند، چون `agent_expectations` باید همان چیزی
را بسنجد که واقعاً گفته می‌شود. اگر پرامپت را تغییر دادید، سناریوها را هم به‌روز
کنید — و آن‌ها را به انگلیسی برنگردانید.

یک نکته‌ی ظریف در پرامپت: قالب نام کاربری `\دامنه\نام‌کاربری` عمداً با نمونه‌ی
لاتین و داخل بک‌تیک آمده و از مدل خواسته شده حرف‌به‌حرف توضیحش دهد. کل سناریوی
آموزشی روی همین قالب بنا شده و در متن فارسی به‌سادگی وارونه فهمیده می‌شود. فیلدهای
ورود در اپ دمو هم به همین دلیل `dir="ltr"` هستند.

## ⚠️ وابستگی ابزار unblock_user به اپ دمو

`unblock_user` مسدودیت را با **پاک کردن فایل روی دیسک** برمی‌دارد:
`../demo-app/public/blockusers.txt` (مسیر در `src/tools.py` از `parents[2]`
ساخته می‌شود؛ اگر فایل‌ها را جابه‌جا کردید، آن را اصلاح کنید — تست
`test_block_file_points_at_demo_app` نگهبانش است).

دو پیامد که باید بدانید:

1. **اپ دمو باید با `npm run dev` اجرا شود، نه بیلد پروداکشن.** در بیلد، `public/`
   در زمان بیلد به `dist/` کپی می‌شود و نوشتن روی فایل مبدأ اثری ندارد.
2. **در کانتینر این ابزار کار نمی‌کند.** بستر ساخت ایمیج `agent/` است و
   `demo-app/` بیرون آن است. ابزار پیام «فایل پیدا نشد» برمی‌گرداند و کرش
   نمی‌کند. این باگ نیست: ایمیج داکر برای استقرار ایجنت روی LiveKit Cloud است و
   اپ دمو یک ابزار نمایش محلی است. اگر لازم شد در کانتینر هم کار کند، متغیر
   `BLOCK_USERS_FILE` مسیر را قابل تنظیم می‌کند.

## تست

دو لایه تست وجود دارد.

**تست‌های سطح-واحد** (`tests/test_agent.py`) منطق ابزارها را پوشش می‌دهند و هیچ
کلید یا شبکه‌ای لازم ندارند، پس در CI اجرا می‌شوند:

```bash
uv run pytest -q
```

**سناریوهای گفت‌وگو** (`scenarios.yaml`) رفتار واقعی ایجنت را می‌سنجند و به
LiveKit CLI نسخه ۲.۱۵+ و کلیدهای معتبر نیاز دارند:

```bash
lk agent simulate --scenarios scenarios.yaml
```

مهم: وقتی رفتار هسته‌ای ایجنت را تغییر می‌دهید — دستورها، توضیح ابزارها،
workflowها — حدس نزنید که چه چیزی کار می‌کند. اول تست بنویسید، بعد کد را تا پاس
شدن تست تکرار کنید.

## Skill رسمی لایوکیت

مخزن یک skill رسمی لایوکیت دارد که در دو مسیر تکرار شده تا هر ابزار نسخه‌ی خودش
را بخواند: `../.claude/skills/livekit-agents/` و `../.agents/skills/livekit-agents/`.
این دو فایل عیناً یکسان‌اند؛ اگر یکی را تغییر دادید، دیگری را هم هماهنگ کنید.

محتوای skill دست‌نخورده و همان نسخه‌ی بالادستی (لایسنس MIT) است. اصول معماری‌اش —
حساسیت به تأخیر، کوچک نگه داشتن context، استفاده از handoff و task، و الزام نوشتن
تست — برای این پروژه هم معتبرند.

**یک مورد با این پروژه نمی‌خواند، و در آن مورد همین فایل اولویت دارد:**

skill استفاده از LiveKit Inference را توصیه می‌کند، ولی این پروژه مستقیماً از
مدل Realtime اوپن‌ای‌آی و آواتار Beyond Presence استفاده می‌کند و به
`OPENAI_API_KEY` و `BEY_API_KEY` جدا نیاز دارد. مهاجرت به Inference یک تصمیم
مستقل است، نه اصلاح جانبی — مدل Realtime یک پارچه صدا-به-صدا است و معادل مستقیمی
در Inference ندارد.

## مستندات LiveKit

LiveKit Agents سریع تغییر می‌کند. برای مرور مستندات:

- **LiveKit CLI:** `lk docs overview`، `lk docs search`، `lk docs get-page`
  (نیازمند نسخه ۲.۱۵+؛ با `lk --version` بررسی کنید). نصب:
  `brew install livekit-cli` روی مک، `curl -sSL https://get.livekit.io/cli | bash`
  روی لینوکس، `winget install LiveKit.LiveKitCLI` روی ویندوز.
- **MCP Server:** `https://docs.livekit.io/mcp` با ترانسپورت Streamable HTTP.

مستندات آنلاین همین نسخه‌ای را توصیف می‌کنند که پروژه استفاده می‌کند، پس
نمونه‌کدها قابل استفاده‌اند. برای امضای دقیق توابع، سورس نصب‌شده در `.venv`
مرجع قطعی است.

اگر از CLI یا MCP برای جست‌وجوی مستندات استفاده کردید، بازخورد سازنده را با
`lk docs submit-feedback` یا ابزار `submit_docs_feedback` به LiveKit بفرستید.

## Handoffs و tasks (workflowها)

ایجنت‌های صوتی به تأخیر زیاد حساس‌اند. برای همین بهتر است ایجنت‌های پیچیده
ساختارمند طراحی شوند تا مقدار context بی‌ربط و ابزارهای غیرلازم در هر درخواست به
LLM کم شود. LiveKit Agents از handoff (واگذاری کنترل از یک ایجنت به دیگری) و task
(پرامپت‌های محدود برای رسیدن به یک نتیجه‌ی مشخص) پشتیبانی می‌کند. به‌جای نوشتن
پرامپت‌های طولانی که چند فاز گفت‌وگو را پوشش می‌دهند، از این‌ها استفاده کنید.
جزئیات: https://docs.livekit.io/agents/build/workflows/
