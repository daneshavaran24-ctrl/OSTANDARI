# استقرار روی لیارا

## خلاصه

یک اپ داکری که **هر دو فرایند** را اجرا می‌کند: رابط کاربری و پنل ادمین
(Next.js) و ایجنت صوتی (Python).

چرا یکی؟ چون هر دو به **یک فایل SQLite مشترک** نیاز دارند: پنل تنظیمات و
کلیدها را می‌نویسد و ایجنت می‌خواندشان، و ایجنت رونوشت گفت‌وگو را می‌نویسد و
پنل نشانش می‌دهد. دو اپ جدا یعنی دو فایل‌سیستم جدا و این پیوند می‌شکند.

هزینه‌اش صریح است:

- مقیاس‌دهی جداگانه‌ی ایجنت و فرانت‌اند ممکن نیست
- مرگ هر فرایند، کل کانتینر را ریستارت می‌کند

اگر روزی ترافیک بالا رفت، مهاجرت به دو اپ + یک پایگاه داده‌ی مدیریت‌شده یک کار
مستقل و مشخص است.

## ۱. اپ را در پنل لیارا بسازید

پلتفرم: **docker**

## ۲. دیسک بسازید و سوار کنید

| نام | مسیر |
|---|---|
| `data` | `/app/data` |

🔴 **بدون دیسک، هر استقرار تازه همه‌چیز را پاک می‌کند**: تنظیمات، کلیدهای API،
محدودیت‌های موضوعی و کل تاریخچه‌ی گفت‌وگوها.

کانتینر خودش این را بررسی می‌کند: اگر مسیر قابل نوشتن نباشد، با پیام روشن بالا
نمی‌آید به‌جای اینکه بی‌صدا یک پایگاه داده‌ی موقت بسازد.

## ۳. متغیرهای محیطی

| متغیر | لازم؟ | مقدار |
|---|---|---|
| `DATABASE_PATH` | ✅ | `/app/data/ostandari.db` |
| `LIVEKIT_URL` | ✅ | `wss://<project>.livekit.cloud` |
| `LIVEKIT_API_KEY` | ✅ | از داشبورد LiveKit |
| `LIVEKIT_API_SECRET` | ✅ | از داشبورد LiveKit |
| `OPENAI_API_KEY` | ✅ | مدل Realtime |
| `ENCRYPTION_KEY` | ✅ | `openssl rand -base64 32` |
| `ADMIN_PASSWORD` | ✅ | رمز پنل؛ خالی یعنی پنل غیرفعال |
| `ACCESS_CODE` | 🔴 | بدونش هر کسی روی اینترنت می‌تواند گفت‌وگو شروع کند و هزینه‌ی مدل بسازد |
| `EMAIL_ALLOWED_DOMAINS` | 🔴 | بدونش ایجنت می‌تواند به هر نشانی ایمیل بفرستد |
| `BEY_API_KEY` / `BEY_AVATAR_ID` | اختیاری | خالی یعنی فقط صدا، بدون آواتار تصویری |
| `GMAIL_USER` / `GMAIL_APP_PASSWORD` | اختیاری | فقط برای ابزار ارسال تیکت |
| `AGENT_NAME` | اختیاری | پیش‌فرض `ostandari-support` |
| `SMS_ENABLED` | اختیاری | `0` یعنی ابزار پیامک اصلاً ساخته نمی‌شود (پیش‌فرض) |
| `GHASEDAK_API_KEY` / `GHASEDAK_LINE_NUMBER` | اختیاری | فقط اگر پیامک لازم دارید — ولی بهتر است از پنل واردشان کنید |

⚠️ عوض کردن `ENCRYPTION_KEY` کلیدهای ذخیره‌شده در پنل را **غیرقابل‌خواندن**
می‌کند. ایجنت در آن حالت به متغیرهای محیطی برمی‌گردد و هشدار لاگ می‌کند، ولی
باید کلیدها را در `/admin/keys` دوباره وارد کنید.

## ۴. توکن و نام اپ را در GitHub بگذارید

`Settings → Secrets and variables → Actions`

تب **Secrets**:

| نام | مقدار |
|---|---|
| `LIARA_TOKEN` | توکن حساب لیارا |

تب **Variables**:

| نام | مقدار |
|---|---|
| `LIARA_APP` | نام اپ شما در لیارا |
| `LIARA_REGISTRY` | اختیاری — `ghcr` (پیش‌فرض) یا `dockerhub` |

`LIARA_APP` متغیر است نه راز، چون رویداد `push` ورودی دستی ندارد و نام اپ باید
از جایی خوانده شود. بدون آن، ورک‌فلو در **اولین گام** با پیام روشن می‌ایستد.

🔴 توکن را در هیچ فایلی از مخزن نگذارید. CI تاریخچه را برای کلیدهای نشت‌کرده
اسکن می‌کند و همین‌جا جلویتان را می‌گیرد.

## ۵. استقرار

### 🔴 دکمه‌ی «استقرار» در پنل لیارا را نزنید

این مهم‌ترین جمله‌ی این سند است. آن دکمه سورس را آپلود می‌کند و ایمیج را **روی
خود لیارا** می‌سازد — همان کاری که در بخش بعدی با عدد نشان داده شده که در مهلت
بیلد جا نمی‌شود. خطای «بیش از ۵ دقیقه» دقیقاً از همین‌جا می‌آید، و هیچ تنظیمی
در این مخزن نمی‌تواند جلویش را بگیرد.

### ⚠️ پیش‌نیاز: شاخه‌ی `main` باید وجود داشته باشد

امروز این مخزن **شاخه‌ی `main` ندارد**؛ شاخه‌ی پیش‌فرضش
`claude/fervent-cannon-lmlahf` است. تا وقتی `main` ساخته نشود، استقرار خودکار
هیچ‌وقت اجرا نمی‌شود — بی‌صدا، بدون خطا.

یک بار، از روی شاخه‌ی فعلی:

```bash
git checkout -b main && git push -u origin main
```

و بعد در گیت‌هاب: `Settings → General → Default branch` و `main` را پیش‌فرض
کنید. از آن پس مدل کار این است:

| شاخه | نقش |
|---|---|
| `claude/…` یا هر شاخه‌ی کاری | توسعه؛ پوش روی آن هیچ استقراری راه نمی‌اندازد |
| `main` | تولید؛ هر ادغام یعنی یک استقرار |

### راه درست

**ادغام در `main` یعنی استقرار.** ورک‌فلو خودکار اجرا می‌شود، ایمیج را در
GitHub Actions می‌سازد، به رجیستری می‌فرستد، و لیارا فقط می‌کشدش.

شاخه‌های کاری آزادند؛ پوش روی آن‌ها هیچ استقراری راه نمی‌اندازد.

برای استقرار دستی (مثلاً از یک شاخه، یا با نام اپ دیگر):

```
Actions → Deploy to Liara → Run workflow
```

ورودی‌ها اختیاری‌اند و فقط متغیرهای بالا را موقتاً کنار می‌زنند.

### گام دستی، فقط بار اول

بعد از اولین اجرای موفق، بسته‌ی رجیستری را عمومی کنید:

```
صفحه‌ی مخزن → Packages → ostandari
  → Package settings → Change visibility → Public
```

لیارا ایمیج را **بدون اعتبارنامه** می‌کشد؛ تا وقتی بسته خصوصی باشد نمی‌تواند.
ورک‌فلو این را بررسی می‌کند ولی عمداً متوقف‌کننده نیست، پس در لاگ به‌صورت
هشدار می‌بینیدش.

### ورک‌فلوی سبز یعنی سایت بالا آمد

گام استقرار `--detach` ندارد، پس منتظر می‌ماند تا ریلیز واقعاً آماده شود. اگر
اجرا سبز است، اپ بالا آمده — نه اینکه فقط دستور فرستاده شده باشد.

## ⚠️ بیلد روی خود لیارا جواب نمی‌دهد

این را با سه استقرار واقعی آزمودیم. اندازه‌گیری از لاگ آخر:

```
02:06:46  شروع
02:08:27  pnpm install تمام شد   ←  ۱ دقیقه و ۴۱ ثانیه، حدود ۲۰٪ کار
```

باقی‌مانده: بیلد Next (حدود ۹۰ ثانیه)، بیش از **۵۵۰ مگابایت** وابستگی پایتون
(`livekit` حدود ۲۴۹ و `av` و کتابخانه‌هایش حدود ۱۱۴ مگابایت)، و کپی حدود
۱٫۳ گیگابایت در مرحله‌ی رانتایم. یعنی ۷ تا ۱۰ دقیقه — بیرون از مهلت بیلد لیارا.

کش هم نجاتش نداد: در تلاش سوم فقط دو گام اول کش شدند و `pnpm install` دوباره
هر ۴۸۷ بسته را از صفر گرفت (`reused 0`). حتی یک `ENV` ساده ۱۷ ثانیه طول کشید.

**پس ایمیج در GitHub Actions ساخته و به یک رجیستری فرستاده می‌شود و لیارا فقط
آن را می‌کشد.** کشیدن ایمیج موازی و CDN-دار است؛ دانلود سریالی wheel و npm نیست.

### اجرا

```
Actions → Deploy to Liara → Run workflow
```

| ورودی | پیش‌فرض | کار |
|---|---|---|
| `app` | — | نام اپ در لیارا |
| `registry` | `ghcr` | ایمیج کجا منتشر شود |

### 🔴 گام دستی بار اول

لیارا ایمیج را **بدون اعتبارنامه** می‌کشد، پس مخزن رجیستری باید عمومی باشد.

**اگر `ghcr` را انتخاب کردید** (بدون نیاز به حساب تازه): بسته‌ها بار اول خصوصی
ساخته می‌شوند. بعد از اولین اجرا:

```
GitHub → صفحه‌ی مخزن → Packages → ostandari
  → Package settings → Change visibility → Public
```

**اگر `dockerhub` را انتخاب کردید**: دو secret لازم است —
`DOCKERHUB_USERNAME` و `DOCKERHUB_TOKEN` — و مخزن باید public باشد.

> داکرهاب یک مزیت اثبات‌شده دارد: بیلدهای قبلی لیارا ایمیج
> `node:22-bookworm-slim` را از داکرهاب با موفقیت کشیدند، پس آن مسیر شبکه
> کار می‌کند. درباره‌ی `ghcr.io` از زیرساخت لیارا چنین شواهدی نداریم. اگر
> `ghcr` نشد، `dockerhub` را امتحان کنید.

ورک‌فلو قبل از استقرار یک بررسی «آیا ناشناس قابل کشیدن است؟» انجام می‌دهد، ولی
**عمداً استقرار را متوقف نمی‌کند** — یک مثبت کاذب در آن بررسی، استقرار سالم را
می‌خواباند که از مشکلی که قرار بود بگیرد بدتر است. اگر هشدارش را دیدید و لیارا
هم نتوانست ایمیج را بکشد، راه‌حل همان‌جا در لاگ نوشته شده است.

## ⚠️ لیارا BuildKit ندارد

بیلد روی لیارا با **بیلدر کلاسیک داکر** انجام می‌شود. هر ویژگی مخصوص BuildKit
آنجا می‌شکند:

```
Step 9/41 : RUN --mount=type=cache,target=/pnpm/store pnpm install
the --mount option requires BuildKit.
```

پس در `Dockerfile` از این‌ها استفاده نکنید:

| ویژگی | جایگزین |
|---|---|
| `RUN --mount=type=cache` | حذفش کنید؛ فقط سرعت بیلد بود |
| `RUN <<EOF` (heredoc) | `RUN` معمولی با `&&` |
| `COPY --link` | `COPY` معمولی |
| `# syntax=` | بی‌اثر است |

یک تله‌ی دیگر که ربطی به BuildKit ندارد ولی همان‌جا می‌شکند: **`ARG`ی که پیش
از اولین `FROM` اعلام شود، داخل هیچ مرحله‌ای در دسترس نیست.** اگر در یک مرحله
لازمش دارید، همان‌جا بدون مقدار دوباره اعلامش کنید:

```dockerfile
FROM ... AS runtime
ARG NODE_VERSION                       # ← بدون این، خط بعدی خالی بسط می‌یابد
COPY --from=node:${NODE_VERSION}-bookworm-slim ...
```

جاب `image` در CI با `DOCKER_BUILDKIT=0` می‌سازد تا همین محیط را بازتولید کند.
**پیش از هر استقرار، آن جاب را اجرا کنید** — چند دقیقه طول می‌کشد و جای یک
چرخه‌ی کند استقرار را می‌گیرد.

## معماری کانتینر

```
 ورودی HTTP (پورت ۳۰۰۰)
        │
        ▼
 ┌──────────────────────────────┐
 │  Next.js  ← رابط کاربری و پنل │
 │            │                  │
 │            ▼                  │
 │   /app/data/ostandari.db      │  ← دیسک ماندگار
 │            ▲                  │
 │            │                  │
 │  Python   ← ایجنت صوتی        │
 │  (سلامت روی ۸۰۸۱، داخلی)      │
 └──────────────────────────────┘
        │
        ▼
   LiveKit Cloud
```

`docker-entrypoint.sh` سه کار می‌کند: مهاجرت پایگاه داده، اجرای ایجنت، اجرای
فرانت‌اند. سپس با `wait -n` منتظر می‌ماند و **اگر هر کدام بمیرد، کانتینر با
همان کد خطا خارج می‌شود**.

این عمدی است: بدونش، مرگ ایجنت بی‌صدا می‌ماند و اپ «سالم» به نظر می‌رسد —
سایت بالاست، دکمه‌ی شروع کار می‌کند، و دستیار هرگز نمی‌آید.

## پیامک (قاصدک)

سه مقدار لازم است: کلید، شماره‌ی خط، و یک کلید روشن/خاموش. **راه درست، پنل
است نه متغیر محیطی**: در `/admin/sms` کلید با AES-256-GCM رمز می‌شود و در
دیسک ماندگار می‌نشیند، پس با هر استقرار تازه پاک نمی‌شود و در متغیرهای محیطی
لیارا به‌صورت متن ساده نمی‌ماند.

ترتیب کار در پنل:

1. **کلید قاصدک** را وارد و ذخیره کنید.
2. **شماره‌ی خط** را بنویسید. اگر خط اختصاصی ندارید، به‌جای شماره یکی از این
   سه کلیدواژه را بگذارید: `priority` (بر اساس اولویت خطوط پنل قاصدک)،
   `fastest` (سریع‌ترین خط) یا `cheapest` (ارزان‌ترین خط).
3. **«آزمایش اتصال»** را بزنید. اعتبار حساب را می‌خواند، پیامکی نمی‌فرستد و
   اعتباری خرج نمی‌کند. این دکمه هم‌زمان دو چیز را می‌سنجد: معتبر بودن کلید، و
   اینکه سرور لیارا واقعاً به `gateway.ghasedak.me` دسترسی خروجی دارد.
4. تازه حالا تیک **«ارسال پیامک فعال باشد»** را بزنید.

تا وقتی کلید و شماره‌ی خط هر دو تنظیم نشده‌اند، روشن کردن آن تیک اثری ندارد و
پنل همین را هشدار می‌دهد. دلیلش عمدی است: ابزاری که وجود داشته باشد ولی کار
نکند، باعث می‌شود دستیار به کاربر وعده‌ای بدهد که نمی‌تواند عمل کند.

🔴 **هر ارسال، تأیید کاربر می‌خواهد.** شماره و متن کامل روی صفحه نشان داده
می‌شوند و بدون تأیید صریح چیزی فرستاده نمی‌شود — سکوت، قطع اتصال و بستن تب همه
«نه» شمرده می‌شوند. این رفتار قابل خاموش کردن نیست.

برای سنجیدن کلید **پیش از** استقرار، روی ماشین خودتان:

```bash
GHASEDAK_API_KEY=... scripts/check-sms.sh
```

## عیب‌یابی

### سایت بالاست ولی دستیار نمی‌آید

به ترتیب بررسی کنید:

1. **لاگ کانتینر**: باید `registered worker` با `agent_name` دیده شود. اگر
   نیست، ایجنت به LiveKit وصل نشده — `LIVEKIT_URL` و کلیدها را ببینید.
2. **اعزام ایجنت**: نام در توکن باید با نام ثبت ایجنت یکی باشد. اگر
   `AGENT_NAME` را تنظیم کرده‌اید، باید با `@server.rtc_session(agent_name=…)`
   در `agent/src/agent.py` بخواند. این خرابی **هیچ خطایی تولید نمی‌کند**.
3. **اعتبار کلید اوپن‌ای‌آی**: در لاگ دنبال `OpenAI Realtime API` بگردید.

### تنظیمات پنل بعد از استقرار پاک می‌شوند

دیسک سوار نشده است. کانتینر در این حالت اصلاً بالا نمی‌آید، پس اگر اپ کار
می‌کند ولی داده‌ها می‌پرند، `DATABASE_PATH` به جایی بیرون از دیسک اشاره دارد.

### ابزار رفع مسدودیت کار نمی‌کند

درست است و طبیعی. آن ابزار به `demo-app/public/blockusers.txt` روی دیسک
وابسته است و اپ دمو مستقر نمی‌شود. ایجنت پیام تمیز برمی‌گرداند و کرش نمی‌کند.

### «آزمایش اتصال» می‌گوید اتصال برقرار نشد

اول مطمئن شوید کلید درست است (همان اسکریپت بالا، روی ماشین خودتان). اگر کلید
آنجا کار می‌کند ولی در پنل نه، مشکل دسترسی خروجی سرور لیارا به
`gateway.ghasedak.me` است.

اگر پیام می‌گوید کلید نویسه‌ی غیرمجاز دارد، کلید را دوباره از پنل قاصدک کپی
کنید: یک نویسه‌ی فارسی یا فاصله‌ی نامرئیِ همراهِ کپی کافی است تا سرتیتر HTTP
نامعتبر شود.

### اگر پشت پروکسی سازمانی هستید

`livekit-agents` مقدار `HTTPS_PROXY` را برای **همه‌ی** اتصال‌ها به کار می‌برد و
`NO_PROXY` را نادیده می‌گیرد. اگر سرور LiveKit داخلی دارید، وب‌سوکت کارگر هم
از پروکسی رد می‌شود و با ۴۰۵ شکست می‌خورد.

| مورد | کجا اثبات شد |
|---|---|
| مهاجرت، اجرای هر دو فرایند، مرگ یکی → توقف کانتینر | تمرین محلی بدون داکر |

| اتصال به لیارا و سوار شدن دیسک | ❌ فقط استقرار واقعی |
