# دستیار هوشمند پشتیبانی استانداری

دستیار پشتیبانی فنی صوتی با آواتار تصویری. کاربر با دستیار حرف می‌زند، صفحه‌ی
نمایشش را به اشتراک می‌گذارد، و دستیار مشکل را می‌بیند، راهنمایی می‌کند، در صورت
لزوم مسدودیت حسابش را برمی‌دارد و خلاصه‌ی تیکت را برایش ایمیل می‌کند.

کل گفت‌وگو فارسی است.

## معماری

       │                                   ┌──────────────┐

| پوشه | چیست |
|---|---|
| `frontend/` | رابط کاربری گفت‌وگو (Next.js 15، React 19). توکن‌سرور LiveKit را هم خودش دارد. |

## راه‌اندازی

### ۱. متغیرهای محیطی

```bash
cp .env.example agent/.env.local
cp .env.example frontend/.env.local
```

بعد هر دو فایل را پر کنید. کلیدهای لازم:

| کلید | از کجا | برای کدام بخش |
|---|---|---|
| `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` / `LIVEKIT_URL` | داشبورد [LiveKit Cloud](https://cloud.livekit.io) | هر دو |
| `OPENAI_API_KEY` | [platform.openai.com](https://platform.openai.com/api-keys) | `agent/` |
| `BEY_API_KEY` / `BEY_AVATAR_ID` | [Beyond Presence](https://bey.dev) | `agent/` |
| `GMAIL_USER` / `GMAIL_APP_PASSWORD` | [رمز اپلیکیشن گوگل](https://myaccount.google.com/apppasswords) | `agent/` |

`GMAIL_APP_PASSWORD` باید «رمز اپلیکیشن» باشد، نه رمز اصلی حساب گوگل.

### ۲. ساخت پایگاه داده‌ی مشترک

پنل ادمین و ایجنت یک فایل SQLite مشترک دارند. یک بار بسازیدش:

```bash
node db/migrate.mjs
```

اجرای دوباره بی‌خطر است. مسیر پیش‌فرض `data/ostandari.db` است و با
`DATABASE_PATH` قابل تغییر. اگر این فایل نباشد، **ایجنت باز هم کار می‌کند** و
مثل قبل همه‌چیز را از `.env.local` می‌خواند — فقط رونوشت گفت‌وگو ثبت نمی‌شود و
محدودیت موضوعی اعمال نمی‌شود.

برای پنل ادمین این دو را هم در `frontend/.env.local` بگذارید:

```bash
ENCRYPTION_KEY=$(openssl rand -base64 32)
ADMIN_PASSWORD=یک-رمز-قوی
```

### ۳. اجرای هر سه بخش

هر کدام در یک ترمینال جدا:

```bash
# اپ دمو  →  http://localhost:8080
cd demo-app && npm ci --legacy-peer-deps && npm run dev

# ایجنت
cd agent && uv sync && uv run src/agent.py dev

# رابط کاربری  →  http://localhost:3000
cd frontend && pnpm install && pnpm dev
```

| سرویس | نشانی | نکته |
|---|---|---|
| رابط کاربری | `http://localhost:3000` | اینجا با دستیار حرف می‌زنید |
| اپ دمو | `http://localhost:8080` | باید با `dev` اجرا شود، نه بیلد |
| ایجنت | — | پورتی باز نمی‌کند؛ به اتاق LiveKit وصل می‌شود |

بدون فرانت‌اند هم می‌توانید ایجنت را در ترمینال بیازمایید (بدون آواتار تصویری):

```bash
cd agent && uv run src/agent.py console
```

## توسعه روی ویندوز

هر سه بخش روی ویندوز کار می‌کنند و **همان دستورهای بالا بی‌تغییر در PowerShell
اجرا می‌شوند** — چون `uv run`، `pnpm` و `npm` خودشان محیط را پیدا می‌کنند و نیازی
به فعال‌سازی دستی venv نیست.

دو تفاوت عملی:

**۱. بازنشانی دمو.** اسکریپت `reset-demo.sh` یک اسکریپت bash است و در PowerShell
اجرا نمی‌شود. معادل ویندوزی‌اش در کنارش هست:

```powershell
.\demo-app\reset-demo.ps1
```

هر دو اسکریپت بایت‌به‌بایت یک خروجی می‌دهند (بدون BOM، پایان خط یونیکس).

**۲. فعال‌سازی دستی venv**، اگر لازم شد. مسیر روی ویندوز `Scripts\` است نه `bin/`:

```powershell
cd agent
uv sync
.\.venv\Scripts\Activate.ps1
```

ولی با `uv run src/agent.py dev` یا `task dev` هیچ‌وقت به این نیاز پیدا نمی‌کنید.

> **پوشه‌ی `.venv` را کامیت نکنید.** از قبل در `.gitignore` است و uv هم خودش یک
> `.gitignore` با محتوای `*` داخلش می‌گذارد. روی ویندوز حجمش حدود ۲۸ مگابایت فایل
> اجرایی است (`python.exe`، `ruff.exe` و بقیه) که روی هیچ سیستم دیگری کار
> نمی‌کند و با یک `uv sync` در چند ثانیه بازساخته می‌شود.

## سناریوی دمو

۱. در `http://localhost:8080` با این اطلاعات وارد شوید:

   | | |
   |---|---|
   | نام کاربری | `\vienna\maxman123` |
   | رمز عبور | `passw0rd` |

   پیام «حساب کاربری شما مسدود شده است» را می‌بینید.

۲. در `http://localhost:3000` روی **شروع گفت‌وگو** بزنید. آواتار به فارسی سلام می‌کند.

۳. بگویید نمی‌توانید وارد سامانه شوید. دستیار از شما می‌خواهد صفحه‌ی نمایش را به
   اشتراک بگذارید؛ پنجره‌ی اپ دمو را انتخاب کنید.

۴. دستیار پیام مسدودیت را می‌بیند، ابزار `unblock_user` را صدا می‌زند، و یک اعلان
   سبز روی صفحه ظاهر می‌شود. حالا ورود موفق است.

۵. نشانی ایمیلتان را بدهید تا خلاصه‌ی تیکت را بفرستد؛ اعلان آبی دوم ظاهر می‌شود.

برای اجرای دوباره‌ی سناریو، کاربر را دوباره مسدود کنید:

```bash
./demo-app/reset-demo.sh          # لینوکس و مک
.\demo-app\reset-demo.ps1        # ویندوز (PowerShell)
```

## نکته‌های مهم

- **ابزار رفع مسدودیت در کانتینر کار نمی‌کند.** بستر ساخت ایمیج داکر `agent/`
  است و `demo-app/public/blockusers.txt` بیرون آن قرار دارد، پس در کانتینر ابزار
  پیام «فایل پیدا نشد» برمی‌گرداند (کرش نمی‌کند). این محدودیت طبیعی است: ایمیج
  برای استقرار ایجنت روی LiveKit Cloud است و اپ دمو یک ابزار نمایش محلی. اگر لازم
  شد، مسیر را با `BLOCK_USERS_FILE` تنظیم کنید.
- **اپ دمو باید با `npm run dev` اجرا شود، نه `npm run build`.** ایجنت مسدودیت را
  با پاک کردن `demo-app/public/blockusers.txt` روی دیسک برمی‌دارد. در حالت
  توسعه، Vite این فایل را مستقیم از دیسک سرو می‌کند و تغییر بلافاصله دیده
  می‌شود؛ ولی در بیلد پروداکشن، `public/` در زمان بیلد به `dist/` کپی شده و
  نوشتن روی فایل مبدأ دیگر اثری ندارد. اگر مسیر دیگری لازم دارید، متغیر
  `BLOCK_USERS_FILE` را تنظیم کنید.
- **اطلاعات ورود اپ دمو عمداً هاردکد شده‌اند** (`demo-app/src/pages/Login.tsx`).
  این اپ فقط نقش «نرم‌افزار دارای مشکل» را بازی می‌کند و هیچ احراز هویت واقعی
  ندارد. هرگز این الگو را در سامانه‌ی واقعی استفاده نکنید.
- **قالب نام کاربری** (`\دامنه\نام‌کاربری`) هسته‌ی سناریوی آموزشی است. فیلدهای
  ورود عمداً `dir="ltr"` هستند تا بک‌اسلش‌ها در محیط راست‌به‌چپ به‌هم نریزند.
- **صدا و مدل دستیار** با `OPENAI_VOICE` (پیش‌فرض `cedar`، لحن مردانه‌ی بم) و
  `OPENAI_REALTIME_MODEL` (پیش‌فرض `gpt-realtime`) قابل تغییرند.
- **نویزگیر** با `NOISE_CANCELLATION` انتخاب می‌شود:

  | مقدار | چه می‌کند |
  |---|---|
  | `ai-coustics` | پیش‌فرض؛ مدلش با `AI_COUSTICS_MODEL` قابل تغییر است |
  | `bvc` | نویزگیر لایوکیت؛ صدای انسان‌های پس‌زمینه را هم حذف می‌کند |
  | `bvc-telephony` | نسخه‌ی BVC برای صدای باند-باریک تلفنی |
  | `nc` | نویزگیری ساده، بدون حذف صدای انسان‌های دیگر |
  | `off` | خاموش |

  کدام بهتر است به محیط شما بستگی دارد؛ اتاق شلوغ با چند نفر معمولاً از `bvc`
  سود می‌برد. مقدار ناشناخته هنگام شروع خطای روشن می‌دهد، نه بازگشت بی‌صدا به
  پیش‌فرض.
- **آواتار اختیاری است.** اگر `BEY_AVATAR_ID` را خالی بگذارید، ایجنت بالا می‌آید
  و گفت‌وگوی صوتی کار می‌کند، فقط تصویری نمایش داده نمی‌شود. برای تست سریع مفید است.

## پنل ادمین

نشانی: `http://localhost:3000/admin` — با `ADMIN_PASSWORD` وارد می‌شوید. اگر این
متغیر خالی باشد، پنل غیرفعال است و هر تلاش ورود رد می‌شود.

| صفحه | کار |
|---|---|
| `/admin` | مدت هر گفت‌وگو، مدل، صدا، شناسه‌ی آواتار، نویزگیر، ثبت رونوشت و مدت نگه‌داری |
| `/admin/keys` | وارد کردن و جایگزینی کلیدهای اوپن‌ای‌آی و آواتار |
| `/admin/restrictions` | افزودن، حذف و فعال/غیرفعال کردن موضوع‌های ممنوع |
| `/admin/conversations` | فهرست گفت‌وگوها و دیدن رونوشت هرکدام |

هر تنظیمی که در پنل خالی بماند، از `.env.local` خوانده می‌شود. یعنی راه‌اندازی
فعلی شما بدون هیچ تغییری کار می‌کند و پنل فقط روی آن را می‌گیرد.

**کلیدها** با AES-256-GCM و `ENCRYPTION_KEY` رمز می‌شوند و هرگز به مرورگر
برنمی‌گردند؛ فقط چهار کاراکتر آخر و زمان آخرین تغییر نمایش داده می‌شود.

### محدودیت زمانی هر گفت‌وگو

پیش‌فرض **۳۰ ثانیه** است و از پنل قابل تغییر. مهلت در **دو جا** اعمال می‌شود:
شمارش معکوس در مرورگر (برای کاربر) و یک تایمر در خود ایجنت (اجرای واقعی). فقط
سمت مرورگر کافی نیست، چون هر کسی می‌تواند جاوااسکریپت را دور بزند و هزینه‌ی مدل
Realtime همچنان مصرف شود.

> ⚠️ **۳۰ ثانیه برای گردش‌کار کامل پشتیبانی کافی نیست.** پرسیدن مشکل، اشتراک
> صفحه، راهنمایی، گرفتن ایمیل و ثبت تیکت در این زمان جا نمی‌شود. این مقدار برای
> نمایش کیوسکی مناسب است. وقتی مدت کمتر از ۱۲۰ ثانیه باشد، ایجنت خودش می‌داند
> که باید کوتاه پاسخ بدهد و سراغ ثبت تیکت نرود. برای استفاده‌ی واقعی مدت را
> بیشتر کنید؛ پنل هم همین هشدار را نشان می‌دهد.

### محدودیت‌های موضوعی

هر محدودیت یک موضوع دارد و یک پاسخ آماده؛ مثلاً موضوع «مسائل سیاسی» با پاسخ
«در این باره نمی‌توانم صحبت کنم.». موارد فعال در شروع هر نشست به دستورهای مدل
اضافه می‌شوند.

> این **راهنمایی به مدل** است، نه یک فیلتر قطعی. کاربر مصر ممکن است مدل را دور
> بزند. اگر تضمین سخت‌تری لازم دارید، به فیلتر کلیدواژه‌ای یا دسته‌بند جداگانه
> نیاز دارید. جزئیات در `SECURITY.md`.

## امنیت

پیش از انتشار عمومی، [`SECURITY.md`](SECURITY.md) را بخوانید — مدل تهدید،
محافظت‌های موجود و **محدودیت‌های شناخته‌شده** آن‌جا فهرست شده‌اند.

دو تنظیم که قبل از هر استقراری باید انجام دهید:

```bash
ACCESS_CODE=<یک کد قوی>           # وگرنه هرکسی می‌تواند گفت‌وگو باز کند
EMAIL_ALLOWED_DOMAINS=ostandari.ir # وگرنه ایجنت به هر نشانی ایمیل می‌فرستد
```

بدون `ACCESS_CODE` فقط محدودیت نرخ فعال است؛ برای دمو کافی است، برای استقرار
عمومی نه.

## توسعه

```bash
cd agent    && uv run ruff check && uv run ruff format --check && uv run mypy && uv run pytest -q
cd frontend && pnpm lint && pnpm format:check && pnpm typecheck && pnpm test && pnpm build
cd demo-app && npm run lint && npm run typecheck && npm test && npm run build
npx playwright test          # سرتاسری، در مرورگر واقعی
```

همین‌ها در CI هم اجرا می‌شوند (`.github/workflows/build-and-test.yaml`).

برای ایجنت، `taskfile.yaml` هم میان‌برهای آماده دارد:

| دستور | کار |
|---|---|
| `task install` | نصب وابستگی‌ها |
| `task dev` | اجرای ایجنت در حالت توسعه |
| `task console` | گفت‌وگو با ایجنت در ترمینال، بدون فرانت‌اند |
| `task check` | لینت، قالب‌بندی و تست‌ها |
| `task simulate` | اجرای سناریوهای گفت‌وگو (نیازمند LiveKit CLI) |

### تست

| جایی | چه چیزی | چند |
|---|---|---|
| `agent/tests/` | منطق ابزارها، مهارهای امنیتی، نویزگیر، پایگاه داده، رمزنگاری، ساخت پرامپت، پروتکل پیامک | ۱۹۸ |
| `frontend/tests/` | کد دسترسی، محدودیت نرخ، انقضای توکن، رمزنگاری، توکن ادمین، شمارش معکوس، آزمایش اتصال قاصدک | ۱۳۱ |
| `demo-app/tests/` | تشخیص کاربر مسدود | ۱۳ |
| `e2e/` | ورود و رفع مسدودیت، و پنل ادمین از ابتدا تا انتها، در مرورگر واقعی | ۱۴ |

هیچ‌کدام کلید API لازم ندارند و همه در CI اجرا می‌شوند.

```bash
node db/migrate.mjs                  # پیش‌نیاز تست‌های پنل
bash scripts/check-crypto-interop.sh # رمزنگاری Node ⇄ پایتون، هر دو جهت
GHASEDAK_API_KEY=... scripts/check-sms.sh  # کلید قاصدک واقعاً کار می‌کند؟
cd agent    && uv run pytest -q
cd frontend && pnpm test
cd demo-app && npm test
npx playwright test
```

`check-crypto-interop.sh` جداست چون کلیدها را یک زبان رمز می‌کند و زبان دیگری
می‌خواند؛ اگر قالب دو طرف واگرا شود، هیچ تست تک‌زبانه‌ای آن را نمی‌گیرد و خرابی
تازه سر اجرای واقعی معلوم می‌شود.

### آزمون‌های زنده

یک لایه‌ی جدا که **واقعاً روی شبکه** اجرا می‌شود: سرور LiveKit واقعی، ایجنت
پایتون واقعی، مرورگر واقعی.

```bash
npx playwright test -c playwright.live.config.ts --project=rpc
```

این لایه هیچ کلید پولی لازم ندارد و در CI هم اجرا می‌شود. لایه‌ی صوتی
(`--project=voice`) کلید واقعی می‌خواهد و بدون آن خودش را رد می‌کند.

همین لایه دو باگ واقعی را پیدا کرد که هیچ تست دیگری نمی‌گرفت: نرسیدن اعزام
ایجنت به کارگر، و بلوکه ماندن ۱۲۳ ثانیه‌ای ایجنت وقتی کاربر وسط تأییدخواهی تب
را می‌بندد. جزئیات در `e2e/live/README.md`.

تست‌های `agent/tests/test_agent.py` منطق ابزارها را می‌سنجند و هیچ کلید یا شبکه‌ای
لازم ندارند. رفتار گفت‌وگویی در `agent/scenarios.yaml` پوشش داده می‌شود و برای
اجرایش به [LiveKit CLI](https://docs.livekit.io/intro/basics/cli/) نسخه ۲.۱۵+ و
کلیدهای معتبر نیاز دارید:

```bash
cd agent && lk agent simulate --scenarios scenarios.yaml
```

`agent/.dockerignore` فایل‌های `.env*` را کنار می‌گذارد، پس هیچ کلیدی وارد ایمیج
نمی‌شود. **توجه:** در کانتینر، ابزار `unblock_user` کار نمی‌کند چون `demo-app/`
بیرون بستر ساخت ایمیج است — به بخش «نکته‌های مهم» بالاتر نگاه کنید.

## یکپارچگی پیوسته

| ورک‌فلو | چه زمانی | چه کاری |
|---|---|---|
| `build-and-test.yaml` | هر push و PR روی `main` | فرانت‌اند (ESLint، Prettier، typecheck، تست، build)، اپ دمو، ایجنت روی پایتون ۳.۱۱ تا ۳.۱۳، سازگاری رمزنگاری دو زبان، مهاجرت پایگاه داده، تست سرتاسری، و امنیت (audit و اسکن کلید) |
| `simulations.yml` | merge به `main` و اجرای دستی | سناریوهای `agent/scenarios.yaml` را روی LiveKit Cloud اجرا می‌کند |

شبیه‌سازی‌ها inference واقعی مصرف می‌کنند، پس روی هر PR اجرا نمی‌شوند. برای فعال
کردنشان این secretها را در `Settings → Secrets and variables → Actions` تنظیم کنید:

```
LIVEKIT_URL   LIVEKIT_API_KEY   LIVEKIT_API_SECRET
OPENAI_API_KEY
BEY_API_KEY   BEY_AVATAR_ID
```

اگر تنظیم نشده باشند، ورک‌فلو به‌جای شکست با خطای مبهم، تمیز رد می‌شود.

اگر با یک عامل کدنویس روی این پروژه کار می‌کنید، **قبل از هر تغییری در ایجنت،
[`agent/AGENTS.md`](agent/AGENTS.md) را بخوانید.** آن فایل چیزهایی را مستند می‌کند
که از خواندن کد قابل حدس نیستند: چرا ترتیب راه‌اندازی آواتار و صدای پس‌زمینه
اهمیت دارد، و اینکه `participant.kind` یک enum عددی است نه رشته — مقایسه‌ی
رشته‌ای با آن بی‌صدا از کار می‌افتد.

## عیب‌یابی

**آواتار وارد اتاق نمی‌شود یا تصویری نمی‌بینم**
`BEY_API_KEY` و `BEY_AVATAR_ID` را در `agent/.env.local` بررسی کنید. لاگ ایجنت را
ببینید؛ اگر آواتار وصل نشود، گفت‌وگوی صوتی کار می‌کند ولی تصویری نمایش داده
نمی‌شود.

**پیام «دستیار وارد اتاق گفت‌وگو نشد»**
ایجنت در حال اجرا نیست یا با کلیدهای پروژه‌ی دیگری وصل شده. مطمئن شوید
`LIVEKIT_URL` در `agent/.env.local` و `frontend/.env.local` یکی است، و
`uv run src/agent.py dev` در حال اجراست.

**بعد از ۱۵ دقیقه اتصال قطع می‌شود و وصل نمی‌شود**
توکن‌ها TTL پانزده‌دقیقه‌ای دارند و باید خودکار تازه شوند. اگر نمی‌شوند، کنسول
مرورگر را ببینید؛ خطای `/api/connection-details` معمولاً یعنی کلیدهای
`frontend/.env.local` تنظیم نشده‌اند.

**ایجنت مسدودیت را برمی‌دارد ولی ورود همچنان رد می‌شود**
اپ دمو را با `npm run dev` اجرا کرده‌اید؟ در بیلد پروداکشن، `public/` در زمان بیلد
به `dist/` کپی می‌شود و نوشتن ایجنت روی فایل مبدأ اثری ندارد.

**سناریوی دمو بار دوم کار نمی‌کند**
`./demo-app/reset-demo.sh` را اجرا کنید تا کاربر دوباره مسدود شود.

**ایجنت انگلیسی جواب می‌دهد**
`agent/src/prompts.py` را بررسی کنید؛ دستور «همیشه فارسی صحبت کن» باید سر جایش
باشد. توجه کنید که اگر کاربر گفت‌وگو را به زبان دیگری شروع کند، دستیار عمداً به
همان زبان ادامه می‌دهد.

**ایجنت با `bvc` یا `nc` کرش می‌کند (به‌ویژه روی پردازنده‌ی AMD)**
علتش تشخیص غلط نوع پردازنده در OpenBLAS است و از پیام کرش قابل حدس نیست. در
`agent/.env.local` مقدار `OPENBLAS_CORETYPE=Haswell` را تنظیم کنید. مسیر پیش‌فرض
(`ai-coustics`) این مشکل را ندارد.

**اعلان «مسدودیت برداشته شد» ظاهر نمی‌شود ولی ورود کار می‌کند**
اعلان از طریق RPC به کاربر انسانی فرستاده می‌شود و آواتار Beyond Presence هم خودش
یک participant است. اگر فیلتر انتخاب مخاطب در `agent/src/tools.py` دست خورده باشد،
اعلان به آواتار می‌رود. `uv run pytest -q` را اجرا کنید — تست‌ها این حالت را
پوشش می‌دهند.
